## 2. Logic Chain

1. **Outbox FIFO Queue Replay and Atomic Deletion**:
   - From Observation 2, `db.outbox_mutations` contains mutations generated by local CRUD operations with auto-incrementing `id`.
   - In `SyncEngine.drainOutbox()`, querying by `.orderBy('id')` ensures strict FIFO transmission to Supabase PostgREST.
   - Once a mutation upsert/delete succeeds, deleting the mutation by `mutation.id` atomically frees the queue without re-transmitting already-persisted items.

2. **Exponential Backoff on Network Errors**:
   - When a network error occurs during drain (e.g. `Failed to fetch`, HTTP 503), the engine must catch the transient exception rather than crash.
   - Incrementing `mutation.retry_count` and persisting `mutation.last_error` in Dexie provides transparent diagnostic metadata.
   - Calculating `delay = Math.min(1000 * Math.pow(2, retry_count - 1), 30000)` doubles the pause between retries, protecting mobile battery and Supabase rate limits while ensuring automatic recovery when connectivity restores.

3. **Deterministic LWW Conflict Reconciliation & Anti-Resurrection Tombstones**:
   - From Observation 3, `resolveLWW` guarantees mathematically proved commutativity and associativity.
   - When a remote record arrives with `T_remote > T_local`, the remote record replaces the local record in Dexie.
   - When a remote record has `deleted_at !== null` and `updated_at > local.updated_at`, the tombstone wins and is saved to Dexie with `deleted_at`.
   - Because `checklistRepository.getActiveItems()` filters `item.deleted_at === null`, the item disappears from all views and cannot be resurrected by subsequent offline reads.
   - If a local user explicitly re-creates or edits the item *after* the remote delete (`T_local > T_remote`), local wins and `deleted_at` becomes `null`.

4. **Graceful Fallback Mode (`PGRST205`)**:
   - Before the user runs `20261017000000_init_cadence.sql` in their Supabase SQL editor, PostgREST queries return HTTP 404 with error code `PGRST205` ("Could not find the table ... in the schema cache").
   - Catching `PGRST205` and transitioning the engine status to `'fallback_local'` (`fallbackMode = true`) allows all local mutations to remain queued in `db.outbox_mutations` without throwing uncaught exceptions or interrupting the user's checklist interaction.

5. **UI Integration for Settings Sheet & Desktop Header**:
   - From Observations 4 and 5, wiring `useSyncState()` into `src/App.tsx` provides `{ isOnline, isSyncing, user, isGuest, fallbackMode }`.
   - Passing `userEmail={user?.email ?? null}` to `SettingsSheet` dynamically toggles between "Signed In" (with email and "Sign Out" button) and "Guest / Local Storage" (with "Sign In" button).
   - Passing `onSignInClick={() => setIsAuthModalOpen(true)}` connects the button directly to the 6-digit email OTP modal (`AuthModal.tsx`).
   - In `DesktopLayout.tsx`, evaluating `(isSyncing ? "Syncing..." : !isOnline || isGuest || fallbackMode ? "Offline / Local" : "Cloud Synced")` alongside the respective dot classes (`animate-pulse bg-[var(--system-blue)]`, `bg-[var(--system-green)]`, `bg-[var(--system-orange)]` / `bg-[var(--system-gray)]`) fulfills the exact visual specification.
